# 店舗データ

## データ

店舗データは OpenStreetMap 由来の静的 JSON に、系列の公式の店舗一覧で確かめた店（284 店）を足したもの（848 店舗 / 44 都道府県。2026-10-25）。
市区町村と町名だけは座標からの逆引きで補っている（[areas.json](../../data/areas.json)）。
店舗データ自体は実行時に書き換えない。訪問記録はD1の`visits`、匿名の訂正報告は
同じD1の`reports`に入る。報告から店舗データを自動で変更することはない。

- [scripts/data/overpass-query.mjs](../../scripts/data/overpass-query.mjs) — **Overpass のクエリと取得の手順は
  ここ 1 か所だけ。** 全国取得と取り直しが別々に写しを持っていて、条件を足したときに
  全国側だけ直していた（取り直した県だけ古い基準で拾ったデータが混ざる）。
  拾うのは「ラーメン店で店名に家」「店名に家系か既知ブランド」「**現地で入力された説明の欄が
  家系**」の 3 通り。3 つめが無いと、名前に「家」を持たない家系が落ちる
  （実測: 東京都だけで壱角屋・春樹・大和家）。
- [scripts/data/fetch-shops.mjs](../../scripts/data/fetch-shops.mjs) — Overpass API を都道府県ごとに並列 3 で叩く。
  1 県あたり 25〜80 秒かかり、たまに失敗する。失敗した県は
  `node scripts/data/fetch-missing.mjs 京都府 宮城県` で個別に再取得してマージする。
  **失敗が残っていれば異常終了する。** 成功と同じ終了コードで返すと、県ごと欠けた
  osm-raw.json をそのまま次の工程へ渡す。このファイルは gitignore なので控えが無く、
  欠けたまま上書きすると取り直すしかない（実測: 752 → 435 件にした）。
- **Overpass の失敗は 3 通りあり、2 つは黙って通る。**
  ① 504 などの状態コード ② **応答が返らない**（`fetch` が例外を投げるので、状態コードを
  見る再試行には入らない。実測: 落ちた 9 県のうち 7 県がこれ） ③ **area を引けなくても
  HTTP 200 と空配列**（実測: 茨城県が 0 件で「成功」し、投げ直すと 20 件返った）。
  ③ は本当に 0 件の県（富山県・高知県）と区別が付かないので、**0 件は別の
  エンドポイントで 1 度だけ疑い、2 回目も 0 なら受け入れる**。
- [scripts/data/judgments.mjs](../../scripts/data/judgments.mjs) — TypeSafe に投げる質問と閾値。
  **判定を変えるならこのファイルだけ見ればいい。** 他所に判定ルールを散らさないこと。
- [scripts/data/judge-all.mjs](../../scripts/data/judge-all.mjs) — 家系判定を実行して `judged.json` に保存。
  確率も保存するので、閾値だけ変えたときは `data:rescore` が API 無しで作り直す。
- [scripts/data/find-duplicates.mjs](../../scripts/data/find-duplicates.mjs) — 200m 以内のペアが同一店舗かを判定。
- [scripts/data/fill-areas.mjs](../../scripts/data/fill-areas.mjs) — 住所の欠けている店を座標から逆引きする
  （Nominatim）。**OSM のタグには住所がほとんど入っていない**（564 件中 87 件しか
  市区町村を持たず、東京都の町田商店 14 店は 1 件も持たない）ので、同名の店を
  見分けられない。**判定の後・整形の前に実行する**——shops.json を見る作りにすると
  「整形 → 逆引き → もう一度整形」になる。座標が動いた店は引き直す。
- [scripts/data/build-dataset.mjs](../../scripts/data/build-dataset.mjs) — 判定結果の整形と重複除去。判定は持たない。
  areas.json は**欠けているところだけ**に使う（現地で入力された OSM のタグを上書きしない）。

### 判定の段階と住所の出どころ（README から移した）

判定した結果の 564 軒 / 40 都道府県（家系 345・家系の可能性 7・家系か未判定 212。2026-10-11 の `data/shops.json`）。**段階は画面にも README にも出さない**（#144）。

- 出典は [OpenStreetMap](https://www.openstreetmap.org/copyright) の contributors（ODbL）です。
- 家系判定は推定です。OSM のタグを [TypeSafe](https://typesafe.ai) に渡して
  ジャンルを判断させ、既知ブランドの対応表と突き合わせています。3 段階あります。
  - **家系** … 地図の記載が家系を名乗っている、または既知の家系ブランド
  - **家系の可能性** … 名乗ってはいないが、記載からジャンルを家系と推定できる
  - **家系か未判定** … ラーメン店で屋号が「〜家」だが、記載からは判断できない
  - 「記載」は店名だけではありません。OSM の説明欄（`description`）や
    `cuisine:ja` に「横浜家系ラーメン」と書かれている店も「家系」になります。
  - 別ジャンルだと判断できた店（博多・塩・味噌・つけ麺・中華料理店・食堂など）は
    一覧に載せていません。
- **味の傾向は参考値です。** OSM に味のデータは無いため、既知のブランドから
  `直系・濃厚` / `クリーミー` / `チェーン・万人向け` を割り当てています。
  判定できない店舗は `情報なし` になります。
- 営業時間・電話番号も OSM 由来で、実際と異なる場合があります。
- **市区町村と町名は座標から引いています。** OSM の店舗タグに住所はほとんど
  入っておらず（564 件中 87 件）、同じ名前のチェーン店を見分けられないためです。
  座標から補うのは**市区町村と町名まで**で、番地は足しません（店の位置を特定する
  ためではなく、見分けるためです）。**OSM のタグに番地が入っている店（89 件）は、
  そのタグの住所がそのまま出ます**——現地で入力された住所の方が確かなので、
  座標由来の地名で上書きしません。

### データを更新する

```bash
npm run data:fetch    # OSM から取得（20〜30 分）      → data/osm-raw.json
npm run data:judge    # 家系判定（要 TYPESAFE_API_KEY） → data/judged.json
npm run data:dedupe   # 重複判定（要 TYPESAFE_API_KEY） → data/duplicates.json
npm run data:areas    # 住所の逆引き（API キー不要）    → data/areas.json
npm run data:build    # 整形（API キー不要）            → data/shops.json
```

`data:judge` と `data:dedupe` は [TypeSafe](https://typesafe.ai) を使うので
`TYPESAFE_API_KEY` が要ります。`.dev.vars` に書いておけば読まれます
（`node --env-file-if-exists` を使うので Node 22.9 以降）。全件で $0.05 ほど。

`data:judge` は判定済みのものを飛ばすので、取り直しても差分だけで済みます
（タグが変わった要素は判定し直します）。判定されていない要素が残っていると
`data:build` はエラーで止まります。

判定に関わるファイルを変えたときに何を再実行するかは、変えた場所で決まります。
判定の材料（確率・スコア）は保存してあるので、方針を変えるだけなら API は要りません。

| 変えたもの                                                | 再実行するもの                                      | API  |
| --------------------------------------------------------- | --------------------------------------------------- | ---- |
| 家系判定の閾値（`CONFIRMED_AT` など）と `decide()`        | `data:rescore` → `data:areas` → `data:build`        | 不要 |
| `KNOWN_BRANDS` / `EXCLUDE`（`scripts/data/classify.mjs`） | `data:rescore` → `data:areas` → `data:build`        | 不要 |
| 重複の閾値（`SAME_SHOP_AT`）                              | `data:build` だけ                                   | 不要 |
| 質問文（`QUESTIONS`）、`shopState`                        | `data:judge -- --all` → `data:areas` → `data:build` | 要   |
| 重複判定の質問（`PAIR_QUESTION`）、`PAIR_RADIUS_M`        | `data:dedupe` → `data:build`                        | 要   |

**判定を変えたら `data:areas` を挟みます。** 判定が変わると、それまで一覧に
載っていなかった店が載ることがあり、その店の地名はまだ引いていません
（`data:areas` は「いま載る店」だけを対象にするため）。挟まないと、その店だけ
市区町村が空のまま出ます。引き直しは差分だけなので、数秒で終わります。

重複の閾値だけを変えるときは要りません。重複と判定された店も含めて引いてあるので、
どちらが残っても地名は揃っています。

`rescore` は保存済みの確率を `decide()` に通し直すだけで、モデルには問い合わせません。
質問文を変えたら確率そのものが変わるので `rescore` では反映されません。

**対応表（`KNOWN_BRANDS` / `EXCLUDE`）を変えたら `rescore` が要ります。**
表は `knownFacts()` 経由で判定と味の両方に効きますが、OSM のタグは変わらないので
`data:judge` は 1 件も処理しません。`data:build` も保存済みの判定を信じるため、
`rescore` を挟まないと古い分類のままビルドが成功してしまいます。

`SAME_SHOP_AT` は `data:build` が保存済みスコアに毎回当てるので、`rescore` も
`dedupe` も要りません。判定が古いまま進むことはなく、`osm-raw.json` と
食い違っていれば `data:build` がエラーで止まります。

## 確かめた記録（`data/verified.json`、#233・#234）

掲載する店を「人が確かめた事実」だけにするための記録。`data:build` が読むのは、
**今のデータに無い営業中の店を足すところだけ**（下の「今のデータに無い店を足す」）。
「確かめ済み」の印など、表示の切り替えはしない（#233）。
形と、今のデータにある `id` かどうかは [tests/verified.test.ts](../../tests/verified.test.ts) が確かめる。

`data/corrections.json` に入れない理由: あちらは `data:build` が読んで一覧から店を消す。
「公式の一覧に無い」は閉店の確定ではないので、消してはいけない。

1 店 1 件の配列。

### 今のデータに無い店を足す（#240）

```bash
npm run data:geocode   # 公式の住所から座標を引く（API キー不要・約 2.4 秒/件）→ data/verified-geo.json
npm run data:build     # 番地の精度で引けた店を shops.json に足す
```

- 足すのは `id` を持たない `status: open` の記録だけ。`data:geocode` はまだ引いていない住所だけを引くので、
  記録を足したら上の 2 つを流せばよい。住所を直すと鍵（都道府県＋住所）が変わり、引き直される。**座標を引いていない記録が
  あると `data:build` は止まる**（`data:geocode` を忘れたまま、店の欠けた一覧を書き出さないため）
- **座標は国土地理院の住所検索**（`msearch.gsi.go.jp`）。Nominatim は日本の番地をほとんど持たず、
  試した住所は 1 件も返らなかった。国土地理院は当たらなかったときに町や字までで返し、その名前で分かる
- **番地の精度で当たった店だけ足す。** 返ってきた名前が「〜番」「〜番地」「〜番〜号」で終わり、その末尾の
  数字の並び（「一丁目１番」なら 1, 1）が、公式の住所で**同じ町の名前のすぐ後に**同じ順で出るときだけ
  （[scripts/data/verified-shops.mjs](../../scripts/data/verified-shops.mjs) の `isPrecise`）。数字が 1 つ
  住所にあるだけで通すと、丁目と街区を取り違える（「1-20-5」に「一丁目１番」）。町の名前を見ないと、同じ県の
  別の町に当たっても通る（「盛岡市大通1-20-5」に「盛岡市別町一丁目２０番」）。表記の違い（ヶ・ケ・が、字の有無）は
  同じと見る。旧字（「彌富通」と「弥富通」）は見ないので、安全側に落ちる。当たらずに残る数字は 1 つまで
  （「1-1-16」に「一丁目１番」は通る。「大島田1-6-1」に「大島田１番地」は、手前の番号にしか当たっていないので落とす）。
  数字の隣の空白は、番地と建物名の境目として残す（「3-3-2 第1旅客ターミナル」の 1 を番地にしない）。町の中心に置くと、直線距離が
  誤る。当たらなかった店も `precise: false` で残し、何度も引かない。`data:build` も残した名前で確かめ直すので、
  決まりを厳しくしたときは引き直さなくてよい
- 市区町村は、引いた座標から Nominatim で引く（`data:areas` と同じ。一覧のまとめ方を今の店と揃える）。
  **公式の住所の頭と合わなければ使わず、公式の住所の頭から取る**（`splitCity`）。境の近くでは隣の市区町村を
  返す（実測: 練馬区旭町が「板橋区」、豊明市が「名古屋市」）。住所の欄には、公式の住所から市区町村を除いた残り
  （番地まで）を出す
- **記録に無いことは埋めない。** 味は `unknown`（情報なし）、`osmUrl` は OSM にその店がある（`osmId`）ときだけ。
  判定は `confirmed`（系列の公式の一覧に載っていることが「既知の家系ブランド」という定義そのもの）。
  ID は `verified/<都道府県＋住所のハッシュ>` で、訪問記録がこれを指す
- `data:build` は、足す店から 100m 以内にある今の店を**系列を問わずに**全部出す。次のときは足さない
  （`maybeSameShop`）。足すと 1 店が 2 回載る。どちらを残すかは人が確かめて `verified.json` を直す
  - 同じ系列で、公式の一覧に無い（`unlisted`）今の店: 位置か店名が古いだけの同じ店のことが多い（実測: 5m・22m の町田商店）
  - 店名が「横浜家系ラーメン」のような一般名だけの今の店: どの店か分からない（実測: 町田商店 荻窪店の 5m 先）
- **系列の公式の店舗データに緯度経度があれば、それを使う**（#250。今は町田商店だけ）。`verified-geo.json` に
  `source: "chain-list"` と `url` を付けて手で入れる（国土地理院から引いた分は `source` を持たない）。
  `data:build` はこの座標を `isPrecise` に通さない。住所から引いたものではないため。市区町村は国土地理院の分と同じく
  Nominatim で引く。`data:geocode` は鍵がある住所を引かないので、上書きされない
  - 町田商店: 店舗検索（`https://shop.machidashoten.com/japan/all/?page=1`〜`5`）の `__NEXT_DATA__` の
    `shops[]` に、店ごとの `latitude`・`longitude`・`businessStatus`・`openingDate` がある。画面では後から読み込むので、
    一覧の文字だけ見ると座標が無いように見える（10/15 は見落とした）。ブラウザーで 1 ページずつ開いて読む
  - 使ってよいかは確かめてある（2026-10-24）: shop.machidashoten.com・machidashoten.com・gift-group.co.jp に
    利用規約・サイトポリシーは無く（あるのは個人情報保護方針だけ）、robots.txt も取得を止めていない
    （shop は robots.txt 自体が無く 404、ほか 2 つは Sitemap の行だけ）。使うのは店の位置という事実だけで、文章・画像は写さない
  - 壱角家の店舗案内の地図リンクは Google マップなので、座標に使わない
- 出典: 足した店の位置は国土地理院の住所検索か系列の公式の店舗データによるので、画面の下・「データについて」・SEO ページ・README に
  書いてある。画面の下の短い出典（`DATA_CREDIT`）は国土地理院だけを挙げる（国土地理院は出典の表示を求める。町田商店の
  サイトには求める決まりが無い）

| 項目                            | 値                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `id`                            | 今のデータ（`shops.json`）の ID。今のデータに無い店は `id` を持たず、次の 3 つを持つ                   |
| `name`・`prefecture`・`address` | 今のデータに無い店だけ。**公式の情報から**持つ（OSM から写さない）                                     |
| `osmId`                         | 今のデータに無いが `osm-raw.json` にはある店（判定や重複除去で外された）。無ければ持たない             |
| `basis`                         | `chain`（系列。`chain` に系列名）／`self`（店自身が家系と名乗る）                                      |
| `status`                        | `open`／`closed`／`unlisted`（公式の一覧に無い。閉店の確定ではない）                                   |
| `checked`                       | 確かめた日（YYYY-MM-DD）。半年で確かめ直す                                                             |
| `source`                        | `chain-list`（系列の公式の店舗一覧）／`official-site`／`official-sns`／`owner-visit`（オーナーの実食） |
| `url`                           | 確かめた先。画面には出さない                                                                           |

- **今のデータにある店は、OSM の店名・座標を写さず `id` で指すだけにする。** OSM（ODbL）の
  データと、自分で確かめた事実を別のデータとして分けておくため（OSMF の Collective Database
  Guideline）。結論の経緯は #234。出典の表示は地図の角・README・規約にあるもので足りる
- 確かめる先は公式の情報だけ。ラーメンデータベースの検索結果やまとめサイト、Google マップの情報は写さない。
  公式サイトも人と同じ速さで 1 ページずつ見て、店舗一覧の文章・画像は写さない（持つのは店名・住所・状態だけ）
- 公式の一覧と今のデータは、店名（支店名）と住所の町名で突き合わせる。公式の一覧に座標があれば（町田商店）、
  その座標と OSM の位置の距離で突き合わせる（実測: 同じ店は 6〜10m。#250）。座標が無い系列は次のとおり。
  町名がずれるときは、公式の住所を町名まで Nominatim で引き、OSM の位置から 800m 以内なら同じ店とする。
  離れていれば同じ店と決めず、今のデータの店を `unlisted`、公式の店を足す候補として両方残す。
  ただし町が広いと、町の中心からの距離は当てにならない（実測: 八王子市片倉町で約 1km）。
  系列の名前が同じで、近くにほかの候補が無ければ同じ店とする
- **同じ会社の公式の一覧どうしが食い違うときは、その系列自身の一覧を正とする。** グループ会社の
  別ブランドのページは更新が遅れることがある（実測: 壱七家のページにだけ魂心家 2 店が残っていた）。
  片方にしか無い店は記録しない。OSM の店名が改名前のまま（例: 「壱七家」→ 本厚木魂心家）のことも
  あるので、住所が合えば今の系列の店として記録する
- **OSM の店名に系列の名前が入っていない店も、住所で突き合わせる。** 公式の一覧では
  「町田商店 志木店」なのに、OSM では「横浜家系ラーメン志木商店」のように系列名の無い
  名前で載っている店がある。OSM の店名で系列を探すと漏れる
  （実測: #234 で志木・綱島・箕面・黒磯の 4 店。足す候補として記録したあと、#236 で同じ店と分かった。
  公式の店舗名は #248 で確かめた）
- **系列の公式の一覧に、別ブランドの店が載っていることがある。** 系列名で一覧を読むと漏れる。
  一覧の全部の店を見て、同じ会社が運営すると書いてあれば `chain` はその系列名にする
  （実測: 壱八家の一覧の「らーめん半蔵 東戸塚店」。#234 で漏れ、#291 で足した）
- **一覧に載っていても営業中とは限らない。店ごとの注記を読む。** 公式の一覧には、開店前の店
  （「10月26日 OPEN！」）や閉店した店（「閉店のお知らせ」）も載っている（実測: 壱角家の一覧で
