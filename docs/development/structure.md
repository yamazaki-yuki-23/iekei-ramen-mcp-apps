# ディレクトリ構成の決まり

ファイルをどこに置き、どう名付けるか。初めて読む人がどこに何があるかを置き場から分かり、1 つの変更で触る場所が散らばらないようにする（#217・#220）。

**主な決まりは lint とテストで強制する。** 文書に書くだけだと崩れるので、下の「強制のしかた」の表にある決まりは、守れていないと `npm run lint` か `npm test` が落ちる。表に無いことはコードレビューで見る。決まりを変えるときは、この文書と強制の設定を同じ PR で直す。

> **移す途中（#220）。** この文書は移し終えた後の形を書いている。#220 の PR 2・3 が入るまで、今のファイルは古い場所・古い名前のままで、**lint とテストの強制もまだ効いていない**（PR 2 で置き場、PR 3 で名前の強制を入れる）。それまでは、この文書を見て手で守る。

## 置き場の決まり

上から順に当てる。`src/` のトップでも、各機能の中でも、同じ決まりを使う。例外は作らない。

### 1. 使う範囲で階層を決める

| 使う範囲                                                                                           | 置く階層           |
| -------------------------------------------------------------------------------------------------- | ------------------ |
| 1 つの機能だけ                                                                                     | `features/<機能>/` |
| `server/` だけ                                                                                     | `server/`          |
| `scripts/` だけ                                                                                    | `scripts/`         |
| 2 つ以上（機能・`server/`・`scripts/` を 1 つずつ数える。`server/` と `scripts/` の 2 つでもよい） | `src/` のトップ    |

1 つの機能だけが使うものは、外部に触るかどうかにかかわらず機能の中に置く。 テスト（`tests/`・`e2e/`）と、ほかのコードを測るだけのスクリプト（`scripts/benchmark-*.mjs`）は、使う側に数えない（製品の一部ではないので、測る相手の置き場を動かす理由にならない）。

### 2. 種類でフォルダを決める

**表の上から順に当て、最初に当てはまったフォルダに置く。** React の部品は、外部のライブラリ（Leaflet・MCP）を使っていても `components/` に置く。

| フォルダ      | 置くもの                                                                                                                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| （直下）      | 入口（`main.tsx`）と画面全体の部品（`<機能名>App.tsx`）だけ。ほかの部品は `components/`。`src/` のトップの直下にはファイルを置かない                                                                     |
| `components/` | React の部品（`.tsx`）。部品専用の CSS はその隣に置く                                                                                                                                                    |
| `hooks/`      | フック。1 ファイルに 1 つ                                                                                                                                                                                |
| `types/`      | 型だけのもの                                                                                                                                                                                             |
| `lib/`        | **外部に触るもの。** 通信、ブラウザの機能（位置・保存・音・描画・振動・画面の要素）、外部のライブラリ                                                                                                    |
| `utils/`      | **外部に触らないもの。** 入力から出力を返すだけの関数と、決まった値                                                                                                                                      |
| `styles/`     | 部品の隣に置かない CSS。機能の中は、2 つ以上の部品で使う `<機能名>.module.css` と、1 つの入口だけが使う `main.css`・`main-<場所>.css`。`src/` のトップは全ページ共通の CSS（名前は下の「名前の決まり」） |
| `generated/`  | **ビルドが作るファイルだけ**（`src/generated/app-html.ts`。`server/` が読む）。Git に入れず、手で書かない。`src/` のトップにだけ置く                                                                     |

- 部品・フック・型でないファイルは、1 つでも外部に触る処理があれば `lib/`（`crypto.randomUUID()` や `setTimeout` も外部に数える）
- ファイルの無いフォルダは作らない
- **2 つ以上の機能で使う見た目は、共有の部品（`src/components/`）とその部品専用の CSS にして共有する。** 部品にできない CSS を 2 つ以上の機能で使うときは、全ページ共通（`src/styles/`）に入れる。一部の機能だけが読む CSS の置き場は作らない（機能どうしは import しないので、どの機能にも置けない）
- サブフォルダは、**1 つの外部のライブラリにまとまるもの**だけ作る。中の `.ts`・`.tsx` は全部が、そのライブラリを直接か import をたどって使う（部品専用の CSS は部品の隣なので、サブフォルダの中にも置ける）。いまは無い（Leaflet を使う部品は `MapView` だけなので、`components/` の直下に置いている）。それ以外の理由（画面の場所・名前の似たもの）では分けない。互いに呼び合う部品を分けると、`../` を行き来する import が増えるだけになる

### 3. 依存の向き

- 機能どうしは import しない。2 つの機能で使うものはトップへ出す
- トップ（共有）は機能を import しない
- `utils/` は外部のパッケージと、`lib/`・`hooks/`・`components/` の値を import しない（外部に触らないことを保つ）。**型だけの import（`import type`）は許す**（実行時に何もしないため）
- ブラウザのコード（`src/`）は `server/` を import しない
- 実行時の循環 import をしない（型だけの import は JavaScript から消えて動きに関わらないので数えない）

## 名前の決まり

| 種類                                                     | 規則                                                                                                                                                                                                                                         | 例                                              |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 部品（`.tsx`）                                           | PascalCase。export する部品名と同じ。1 ファイルで外へ出す部品は 1 つ                                                                                                                                                                         | `McpConnection.tsx`                             |
| 画面全体の部品                                           | `<機能名>App.tsx`                                                                                                                                                                                                                            | `SearchApp.tsx`・`MatchApp.tsx`                 |
| フック                                                   | `use-<名前>.ts`。export する `use<名前>` と対応させる                                                                                                                                                                                        | `use-slow.ts` ↔ `useSlow`                       |
| `lib/`・`utils/`・`types/`                               | kebab-case                                                                                                                                                                                                                                   | `geo.ts`・`browser-position.ts`                 |
| 入口                                                     | `main.tsx` を 1 つ。入口が 2 つ以上ある機能は、全部を `main-<場所>.tsx` にする（`main.tsx` は置かない）                                                                                                                                      | `main-mcp.tsx`・`main-web.tsx`                  |
| 部品専用の CSS                                           | `<部品名>.module.css`。部品の隣                                                                                                                                                                                                              | `TabBar.module.css`                             |
| 機能の CSS（2 つ以上の部品で使う）                       | `features/<機能>/styles/<機能名>.module.css`。1 つの部品だけが使うなら、部品専用の CSS にする                                                                                                                                                | `search.module.css`                             |
| 全ページ共通の CSS                                       | `src/styles/` に、中身を表す名前。「全ページ」は Vite が組み立てるページ（`index.html`・`mcp-app.html`・各機能の `index.html`）。静的ページ（都道府県・店・規約）は `scripts/build-seo.mjs` が `global.css` を `seo-tokens.css` に写して読む | `global.css`                                    |
| サーバーが返す画面だけが読む CSS                         | `server/styles/` に、中身を表す名前                                                                                                                                                                                                          | `oauth-consent.css`（サインインの同意画面）     |
| 1 つの入口だけが読む、全体に効く CSS（モジュールでない） | `features/<機能>/styles/<入口名>.css`（入口が `main.tsx` なら `main.css`）                                                                                                                                                                   | `main-web.css`（Web のトップの `html`・`body`） |

```
   │  │  ├─ main-mcp.tsx・main-web.tsx・SearchApp.tsx

   │  │  ├─ hooks/・lib/・utils/・types/
   │  │  └─ styles/                  search.module.css・main-web.css
   │  ├─ match/                      家系マッチ（main.tsx・MatchApp.tsx・components/・hooks/・lib/・utils/・styles/）
   │  ├─ camera/                     家系カメラ（main.tsx・CameraApp.tsx・components/・lib/・utils/・styles/）
   │  └─ shindan/                    家系タイプ診断（main.tsx・ShindanApp.tsx・components/・utils/・styles/）
   ├─ components/                    共有の部品（BrandMark・LegalLinks・TabBar・Pending）
   ├─ hooks/                         共有のフック（use-slow）
   ├─ lib/                           共有で外部に触るもの（feed・sound・browser-position）
   ├─ utils/                         共有で外部に触らないもの
   ├─ types/                         共有の型
   ├─ styles/                        全ページ共通の CSS
   └─ generated/                     ビルドが作る HTML（server が読む）
```

## 強制のしかた

新しい依存は足さない。oxlint（`.oxlintrc.json` の `overrides`）で書けるものは lint、書けないものは単体テスト（`tests/structure-*.test.ts`）で見張る。**機械で確かめるのは、この表の行だけ。** 普通に書いたときの崩れ方（置き間違い・名前の付け間違い・向きの逆な import）を止めるためのもので、表に無いこと（わざとすり抜ける書き方や、CSS をどこから読むか）はコードレビューで見る。確かめ方をすり抜けの数だけ増やすと、テストの方が読めなくなる。決まりを変えるときは、この表と確かめ方も同じ PR で直す。

**置き場**

| 決まり                                                                                                                                                                                                            | 確かめ方                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 使う範囲（使う側が 1 つだけなら、その中へ: 機能なら `features/<機能>/`、`server/` なら `server/`、`scripts/` なら `scripts/`。2 つ以上ならトップ。`generated/` はビルドの出力で置き場が決まっているので数えない） | 単体テスト。import をたどり、使う側を機能・`server/`・`scripts/` の単位で数える。テストと `scripts/benchmark-*.mjs` は、たどる対象から外す（トップのものは、トップのほかのファイルを経由した使い手も数える）。トップのものは使う側が 2 つ以上、機能・`server/`・`scripts/` の中のものはその単位の中からだけ使われていることを確かめる |
| `src/` のトップには決まったフォルダ（`features/`・種類のフォルダ・`generated/`）だけがあり、ファイルを置かない                                                                                                    | 単体テスト                                                                                                                                                                                                                                                                                                                            |
| 機能の直下には、入口・`<機能名>App.tsx`・種類のフォルダだけ。入口は `main.tsx` が 1 つだけか、`main-<場所>.tsx` が 2 つ以上                                                                                       | 単体テスト（入口の数と名前の組を確かめる）                                                                                                                                                                                                                                                                                            |
| `components/` には React の部品（`.tsx`）と部品専用の CSS だけ                                                                                                                                                    | 単体テスト                                                                                                                                                                                                                                                                                                                            |
| `hooks/` には、`use-<名前>.ts` に `use<名前>` のフックを 1 つだけ export するファイルだけ                                                                                                                         | 単体テスト（export が 1 つで、名前がファイル名と対応すること）                                                                                                                                                                                                                                                                        |
| フック（`use` で始まる export）は `hooks/` にだけ置く                                                                                                                                                             | 単体テスト                                                                                                                                                                                                                                                                                                                            |
| `types/` には型だけ（JavaScript にすると何も残らない。値の宣言・値の import・再 export・式のどれも無い）                                                                                                          | 単体テスト（ビルドと同じ Vite の oxc で JavaScript にし、型の import だけを消して、空であることを確かめる。型だけのモジュールでも残る `export {};` と空の文 `;` は数えない）                                                                                                                                                          |
| 型だけのファイルは `types/` に置く（`utils/`・`lib/` に置かない）                                                                                                                                                 | 単体テスト（`utils/`・`lib/` の `.ts` を同じ方法で JavaScript にし、何も残らなければ落とす）                                                                                                                                                                                                                                          |
| `lib/` のファイルは外部に触る（決めたグローバル・外部のパッケージの値・ほかの `lib/` の値のどれかを使う。型だけの import は JavaScript から消えるので数えない）                                                   | 単体テスト（`import type` と、中が全部 `type` の `import { type A }` は数えない）                                                                                                                                                                                                                                                     |
| `utils/` は外部に触らない: 決めたグローバル（`window`・`document`・`localStorage`・`fetch`・`crypto`・`setTimeout` など）を使わない                                                                               | lint `no-restricted-globals`                                                                                                                                                                                                                                                                                                          |
| `utils/` は外部に触らない: 外部のパッケージと、`lib/`・`hooks/`・`components/` の値を import しない（型だけは可）                                                                                                 | lint `no-restricted-imports`                                                                                                                                                                                                                                                                                                          |
| `styles/` には CSS だけ                                                                                                                                                                                           | 単体テスト                                                                                                                                                                                                                                                                                                                            |
| サブフォルダは決めた所だけ（テストの表に、まとめる外部のライブラリの名前と一緒に書く）。中の `.ts`・`.tsx` は全部が、そのライブラリを直接か import をたどって使う。部品専用の CSS も部品の隣に置ける              | 単体テスト                                                                                                                                                                                                                                                                                                                            |
| `generated/` にはビルドが作るものだけ（Git に入れない）                                                                                                                                                           | `.gitignore` と単体テスト（Git が追う `src/generated/` のファイルが無いこと）                                                                                                                                                                                                                                                         |
| ファイルの無いフォルダを作らない                                                                                                                                                                                  | Git は空のフォルダを持たないので、手元にできても共有されない（確かめるものが無い）                                                                                                                                                                                                                                                    |

**依存の向き**

| 決まり                                                                                                 | 確かめ方                                                    |
| ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| 機能どうしは import しない・トップ（共有）は機能を import しない・`src/` は `server/` を import しない | lint `no-restricted-imports`                                |
| 実行時の循環 import をしない（型だけの import は数えない）                                             | lint `import/no-cycle`（既定の `ignoreTypes: true` のまま） |

**名前**

| 決まり                                                                                                                                                                                                                      | 確かめ方                               |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `.ts`・`.tsx` の書き方（`components/` の `.tsx` と `<機能名>App.tsx` は PascalCase、それ以外は kebab-case）                                                                                                                 | lint `unicorn/filename-case`           |
| 部品のファイル名は、export する唯一の部品の名前と同じ（PascalCase の `function`・`const`・`class` を部品として数える。SCREAMING_CASE の定数は数えない）                                                                     | 単体テスト                             |
| CSS の名前と置き場（部品専用は `<部品名>.module.css` を部品の隣、機能の CSS は `<機能名>.module.css`、入口だけが読む CSS は同じ名前の入口がある `main.css`・`main-<場所>.css`、全ページ共通は `src/styles/` に kebab-case） | 単体テスト（oxlint は CSS を読まない） |
| サーバーが返す画面だけが読む CSS は `server/styles/` に kebab-case で置く                                                                                                                                                   | 単体テスト                             |

## よくある迷い

| 迷い                                                                              | 置き場                                                   | 理由                                                                                 |
| --------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 探す画面だけが `localStorage` を読む                                              | `features/search/lib/`                                   | 使うのが 1 機能。外部に触るので `lib/`                                               |
| 家系カメラも家系マッチも使う、店を探す接続                                        | `src/lib/feed.ts`                                        | 2 機能が使い、通信する                                                               |
| サーバーと画面の両方が使う、3 軒の選び方                                          | `src/utils/shortlist.ts`                                 | `server/` も 1 つと数える。外部に触らない                                            |
| 地図の部品を後から読み込む仕組み（`lazy()` と先読み）・Leaflet で線や印を描く処理 | `features/search/lib/`（`lazy-map.ts`・`map-layers.ts`） | 部品ではない `.ts` で、外部（`requestIdleCallback`・Leaflet・画面の要素）に触る      |
| MCP と Web につなぐ部品（`McpConnection`・`WebConnection`）                       | `features/search/components/` の直下                     | 使う外部のライブラリが違う（MCP Apps と MCP クライアント）ので、サブフォルダにしない |
