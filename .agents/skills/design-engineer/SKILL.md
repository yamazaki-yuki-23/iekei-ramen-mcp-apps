# design-engineer

UI を触るときの**判断の基準**を持つスキル。進め方は `/ship-issue`、トークンと部品の決まりは
[DESIGN.md](../../../DESIGN.md) が持つ。**値（色・余白・大きさ）はここに書き写さない。**
二重に持つと、片方だけ直したときにずれる。

軸は [DADS](https://design.digital.go.jp/dads/)。見た目の流行より、**誰でも迷わず操作できること**を先に置く。
そのうえで、AI が量産したように見えない、この題材（家系ラーメン）ならではの画面にする。

## 1. 作る前に（5 分）

1. DESIGN.md を全部読む。特に「7. 操作できるもの」「9. 新しい部品を足すときの手順」「10. やらないこと」
2. **その画面で利用者が次に何をするかを 1 文で書く。** 例:「3 軒の中から 1 軒選んで地図アプリで開く」。
   書けないなら作り始めず、issue の目的を読み直すか聞く
3. 既存の部品（カード・チップ・バッジ・空状態）で足りないか見る。足りるなら新しく作らない
4. 状態を全部並べる: 読み込み中・0 件・1 件・多数・失敗・匿名／サインイン済み・明／暗。
   ひとつでも描き方が決まっていなければ、先に決める

## 2. 判断の基準

迷ったら上から順に優先する。

1. **情報が正しい。** 店舗の味・評判・混雑・移動時間を、文言でも見た目でも推測で補わない。
   距離は直線距離と書く。家系判定の段階と但し書きを、飾りのために削らない。
   店舗に差を付ける（1 軒だけ大きく・目立たせる）のは、利用者が選んだときか、事実（距離・判定の段階）に
   根拠があるときだけ。根拠が無ければ同じ扱いで並べる
2. **誰でも操作できる**（DADS の基礎とアクセシビリティの指針）
   - キーボードだけで最後まで操作でき、焦点がいつも見える。要素を作り直したら焦点の行き先を決める
   - 状態を色だけで伝えない。文字か形を併せる
   - 押せるものは押せると分かる形にし、DESIGN.md の大きさを下回らせない
   - 見出し・ボタン・リンクの役割を HTML の要素で表す。`div` に `onClick` を付けない
   - 明暗の両方でコントラスト比を測る（目視で済ませない）
3. **迷わない。** 1 画面で主な行動は 1 つ。いちばん目立つものがそれになっているか確かめる。
   ラベルは動詞で、何が起きるかを書く（「OK」「送信」ではなく「地図で開く」）
4. **この題材らしい。** 色・言葉づかい・余白の取り方を DESIGN.md の家系の決まりに揃える

## 3. AI っぽさを避ける

次のどれかに当てはまったら、作り直す。

| 避けるもの                                     | 代わりにすること                             |
| ---------------------------------------------- | -------------------------------------------- |
| 意味のないグラデーション・ぼかし・光彩         | 面は単色。強弱は余白と文字の大きさで付ける   |
| 見出しの絵文字、「✨」「🚀」                   | 見出しは文字だけ                             |
| 並びの理由が見えないカードの羅列               | 並び順の根拠（距離・名乗りなど事実）を見せる |
| 「〜を探しましょう！」「最高の一杯」などの煽り | 事実と次の行動だけを書く                     |
| 全部を角丸・影・枠で囲む                       | 囲むのはまとまりを示すときだけ               |
| 中身のない飾りの図形・アイコン                 | 情報を持たないものは置かない                 |

## 4. 出す前に確かめる（10 分）

1. `npm run build:ui`（3031 と 8080 のサーバーは止めない）
2. `npx react-doctor@latest design --scope changed --verbose` の指摘が 0 件（design は点数を出さないので、件数で見る）
3. `npm run e2e`。新しく押せるものや状態を足したら、それを見張るテストも足す
4. 明・暗、幅 375px と広い幅の 4 枚を撮って PR に貼る。1 の「次の行動」が
   どの幅でもいちばん目立っているかを、撮った画像で確かめる
5. Tab キーだけで新しい操作を 1 周する。焦点が消えた所・飛んだ所があれば直す

DESIGN.md に無い値や部品が要ったときは、DESIGN.md に段を足してから使う（同じ PR で）。

## やらないこと

- DESIGN.md の値をこのファイルに書き写さない
- 見た目のために、ホストのテーマ・データの但し書き・焦点リングを消さない
- 新しい依存（UI ライブラリ・フォント・アイコン集）を、見た目のためだけに足さない
